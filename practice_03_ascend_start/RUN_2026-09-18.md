## 2. vLLM 离线批处理：修正启动方式后通过

第一次使用默认进程启动方式失败，根因是：

```text
Cannot re-initialize NPU in forked subprocess.
To use NPU with multiprocessing, you must use the 'spawn' start method
```

在该实例已安装的 `vllm/envs.py` 中确认默认值是 `fork`。
设置 `VLLM_WORKER_MULTIPROC_METHOD=spawn` 后，同样的模型和参数生成成功，退出码 0。
`vllm_generate.py` 和 `serve.sh` 已加入该设置。复现命令：

```bash
cd /data/tianchi
export HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1
VLLM_WORKER_MULTIPROC_METHOD=spawn \
python -u practice_03_ascend_start/vllm_generate.py \
  --model /data/huggingface_home/hub/Qwen2.5-0.5B-Instruct
```

本次参数：单卡、BF16、eager、最大上下文 2048、最多 4 条调度序列、
每步 token 预算 2048、`gpu_memory_utilization=0.3`。

日志记录：

- 模型权重用量约 0.93 GiB。
- 可用 KV cache 预算约 17.25 GiB；这是预分配缓存预算，不是两个请求实际需要这么多缓存。
- 引擎 profile / KV cache 创建 / warmup 共 9.68 秒，不含前面的全部启动流程。
- 两个 prompt 均完成；引擎正常关闭。

只验证生成流程，不将进度条显示的 tokens/s 当作正式 benchmark。
输出将 KV cache 泛化成普通键值缓存，并错误地将 prefill 描述成预训练模型，
说明这个小模型的回答不能作为技术解释的依据。正确的概念是：prefill 处理输入 prompt 并生成
各层 K/V；decode 逐 token 生成，复用已有 K/V。
