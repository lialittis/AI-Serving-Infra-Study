# P3b 后续：视觉元数据与主机同步

目标：检验 Practice 25 中先视觉再语言（VL）缺少重叠，是否主要受视觉路径读取设备端分段长度影响；保持 eager、单 CPU 提交线程、同模型/输入和显式事件 handoff。

三组：native 原实现；lengths 只让视觉 attention 使用预先从 CPU grid 得到的分段长度，保留视觉 forward 的其他元数据工作；cached 再预计算窗口索引/逆序、RoPE cos/sin。真实像素始终重新经过 patch embed、32 个视觉 block 和 merger，不缓存视觉特征。局部方法替换仅在本进程生效，退出恢复；源文件哈希不符即拒绝运行。

8 个 P25 场景 × 3 变体 × 单/双流 × LV/VL 两种顺序。每种变体/流模式预热 3 次，12 个计时轮次（每顺序 6 次），交替顺序，每两轮移动六个配置的起始位置；每种顺序下每个配置覆盖全部六个位置。共 576 个无 profiler 样本。另采 96 个 profiler trial。资格检查和每次测量逐元素对比原实现 features/logits/全部 KV，8 格与原生完整 forward/generate 对照。

计时边界沿用 P25；预计算时间和常驻元数据字节单列，不能当作免费工作。统计独立计时的 pair/A/V/B 完成、主机提交、显存；诊断统计实际 kernel 区间交集、视觉原生同步 API 调用和显式依赖。API 可能嵌套，不能把调用次数当作独立等待次数。

验收：正确性通过；所有实验组合完整；所有 kernel CSV 精确关联；数据 handoff 与输出完成要求成立；记录实际同步是否消减及 VL 是否出现真实重叠，无论是否加速均完整报告。归档原始 trace/CSV/环境/源码/失败轮次并独立重放分析。原始已安装软件和 P25 结果保持不变。
