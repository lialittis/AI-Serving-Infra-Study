两个容易漏检的反例
总和相同：[3,5,2] → [4,4,2]，二者总和都是 10，split 接受两者；但第一段多取一个 token，第二段少取一个。
窄化被差分掩盖：累计边界 [0,2147483647,2147483649] 转 int32 后末项变成 -2147483647，但本机差分仍得到 [2147483647,2]。输出逐元素正确也无法证明转换前没有溢出。
正常长度的充分条件：转换前边界从 0 开始、严格递增、最大值不超过 int32 上限。在这些前提下，相邻差值必然处于合法正 int32 范围。独立参考仍用于确认每个边界的业务含义。
